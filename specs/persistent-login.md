# R47 — Persistent application login

Authoritative R47 contract; supersedes R46's in-process 30-minute session lifetime. All owner-only simulator rules remain unchanged.

## Behavior
Successful OAuth login creates one opaque application session valid for seven days (604800 seconds) from exchange, without sliding renewal. Closing all browser windows, reopening Chrome, refreshing, opening another same-origin tab or restarting/deploying the API preserves this session while unexpired and unrevoked. Google credentials/tokens are not stored by this feature. Expiry or Sign out requires another Google login. Incognito, cleared site storage or browser settings that erase site data cannot preserve login.

Keep the existing bearer architecture: persist only the random application token in same-origin localStorage, not profile/permission authority. On startup always validate it with /auth/me before showing protected features. Keep the short-lived PKCE verifier in sessionStorage. This avoids dependency on third-party cookies across the separate Render frontend/backend domains; no Google scopes, consent setting or callback changes. The application token remains JavaScript-accessible under this existing bearer architecture, so retain safe React rendering, no-store responses, HTTPS and source-only script delivery. Never log tokens or place them in URLs.

Sign out revokes the stored server session first, then removes the browser token. Network/storage failure reports a retryable error and never claims confirmed logout. A storage event clears/revalidates other open tabs, so logout propagates across tabs. Invalid/expired tokens are removed; transient server failure retains the browser token for retry but removes protected UI. Server-derived canUseSimulator remains the only permission authority, with verified Google owner email unchanged. No local profile or email may grant access.

## Database contract
Extend specs/database.md with isolated auth_private.application_sessions and auth_private.session_schema_history. Use the existing backend PostgreSQL connection via auth.database-url (AUTH_DATABASE_URL optional override, otherwise simulation.database-url). No new resource, credential, paid plan or manual SQL required. A separate Flyway stream db/auth-migration creates only these new objects, leaving all existing schemas, migration streams, people and simulator/audit data unchanged.

application_sessions: token_hash VARCHAR(43) PRIMARY KEY CHECK length=43; profile TEXT NOT NULL (server-validated provider profile JSON, including emailVerified); created_at TIMESTAMP WITH TIME ZONE NOT NULL; expires_at TIMESTAMP WITH TIME ZONE NOT NULL and greater than created_at; revoked_at TIMESTAMP WITH TIME ZONE NULL. Index expires_at. Store SHA-256 of the 256-bit opaque token, never its plaintext or provider tokens. Recompute capability from stored verified profile on reads; do not persist a permission boolean. Query the database on every authenticated request, enforce expiry/revocation across instances, and clean expired sessions when creating sessions. Transactions make cleanup/creation atomic. Logout revokes the matching hash idempotently. No runtime volatile-session fallback: unavailable database yields safe no-store 503, allowing retry. Public features and health remain independent; short-lived OAuth exchange tickets may remain in memory.

Database Explorer excludes auth_private from both catalog and raw-row discovery, including explicit requests. Authentication data must not be public even to the simulator owner. No frontend database URL.
