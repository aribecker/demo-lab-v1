

## R38 — Separate retained Weather microservice and retire superseded deployments (v2.9.0)
The integrated frontend calls https://ariel-sdd-weather-microservice.onrender.com/api/weather directly for the live weather demonstrator. Preserve that original Render weather service and update its weather-only implementation to the current normalized v2 JSON contract, provider fallback, error and CORS behavior. Remove weather provider/controller/model code and provider properties from the integrated backend; its /api/weather returns404 while /health remains200.
Introduce an independent VITE_BACKEND_API_URL for People, chatbot, authentication and shared simulation. VITE_WEATHER_API_URL exclusively configures weather; changing it must never redirect other API requests. Preserve all routes, existing data, reset semantics, scheduler, login and chatbot behavior. Use the existing shared PostgreSQL connection only in the integrated backend. No new database, reset, paid plan or provider credentials.
Keep canonical weather-only source in weather-microservice/ on the integrated branch; deploy its generated equivalent at weather-service/ on the retained service's existing microservices-v008 branch because connector settings cannot change that service's branch. Keep source provenance explicit and use separate specifications, grounding and generated-code commits on both branches.
After live verification, retain only the integrated frontend, integrated backend, original Weather microservice and shared PostgreSQL from this project. Retire ten obsolete Render services: ariel-demo-next, ariel-demo-next-api, ariel-sdd-hello-world-2-temp, ariel-sdd-people-api, ariel-sdd-chatbot-test, ariel-weather-iteration-2, ariel-weather-api-iteration-2, ariel-sdd-test-java-app, ariel-sdd-test-java-weather, ariel-sdd-weather-java. Preserve unrelated ariel-react-playground and all Git branches/repository history. Deletion is a deployment cleanup, not source or database deletion. Do not claim retirement without confirming actual Render removal.
