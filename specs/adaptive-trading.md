# R43 — Adaptive Bitcoin simulation and teaching panel

## Scope and compatibility
Extend the shared Java simulation at /bitcoin in the integrated zone. No real orders. Preserve existing balances, history, classic strategy and pause state on deployment. Old simulation JSON defaults to classic; next-run settings default to adaptive. Strategy and risk parameters are captured only by explicit Start / Reset. Opening the page never issues commands. Keep global PostgreSQL ownership and command revision/idempotency.

## Observable rules
Aggregate successful sampled ticker prices into UTC one-minute OHLC candles. Close a candle only on a later minute; do not invent missing candles. Indicators use completed candles only: Wilder ATR14 (seed from 14 true ranges using prior close), EMA9 and EMA21 (seed at first completed close, minimum21 completed candles). Candles reflect sampled prices, not exchange-complete OHLC. Require21 completed consecutive sampled minutes (about22 minutes from Reset) before entries. On pause/resume or quote gaps over30 seconds discard indicator warmup and pending entry references; preserve positions, entry, maximum and existing stops. Do not form entries across missing data. Existing protective stops can execute on a fresh valid quote after a gap; fill at that quote, never at a missed stop.

In cash, track a rolling cycle high. Arm a dip when price <= high minus max(dipAtr*ATR, high*minimumMovePercent/100). After arming follow the lowest price. Buy on recovery >= low + max(reboundAtr*ATR, low*minimumMovePercent/100), only when EMA9 >= EMA21. Equality satisfies a threshold. One order maximum per successful quote. Do not enter on first reference or warmup-completion quote. After sell clear the cycle; a new dip and rebound are required.

On buy capture entry and hard stop entry - max(lossAtr*ATR, entry*minimumMovePercent/100). Follow the maximum from entry. Ratchet trailing stop upward to max(previous trailing stop, peak - max(trailAtr*ATR, peak*minimumMovePercent/100)); never loosen it when volatility grows. On price <= hard stop sell for loss protection; otherwise price <= trailing stop sells for retracement. Stops execute even if trend turns bearish or indicators are warming. They may sell at a loss. Preserve fee accounting in received asset, at active fee rate. No promised profits.

Defaults: dipAtr1.5, reboundAtr0.75, trailAtr2, lossAtr3, minimumMovePercent0.2. User may choose classic/adaptive and edit these next-run settings (ATR multiples0.1–20, minimum move0.01–10%). ATR period14, EMA9/21 and candle60s are displayed fixed algorithm parameters. Reject non-finite/out-of-range values and unknown strategies with rollback. Classic minimum/maximum remain live classic-only controls; adaptive uses its own dynamic levels. Changes alone never trade.

## Teaching interface
Use English UI to match the app. Show active strategy versus next-run selection. Display a numbered observe → dip → rebound/trend → hold/exit explanation and server decision text. Show current price/time, freshness/pause status, warmup progress, ATR/ATR percent, EMA9/21 and trend pass/fail, cycle high, dip trigger, dip low, required rebound, buy trigger and remaining distance, entry, peak, hard/trailing/effective stop and remaining distance, drawdown, round-trip fee estimate/break-even, portfolio value and net P/L. Explain formula and units beside each value; absent values are “Waiting”, never zero. Costs are estimates; no spread/slippage/order-size rules. Retain chart, balances and ledger; record explicit adaptive reasons. All values are server snapshots, no second browser trading engine. Central CSS tokens/BEM only; responsive cards and accessible labels; no color-only signals. Source documentation appears automatically in Specifications.
