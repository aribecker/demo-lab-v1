# R46 — Separate market tracker and simulator (historical access baseline)

Current precedence: [demo-lab-access.md](demo-lab-access.md) supersedes this document's fixed owner-only identity and mandatory-login rules. Persisted SIMULATOR memberships, including Everyone, govern access on canonical main. [bitcoin-trading-integration.md](bitcoin-trading-integration.md) provides the consolidated map. The owner-only clauses below describe the historical R46 baseline; route separation, public market projection and API/data protection still apply with the current permission decision.

This specification superseded earlier statements in R15–R18, R32 and R35 that all simulator access and commands were public. Other feature and database contracts remain in force.

## Navigation and views
- `/bitcoin` remains the public **Bitcoin Tracker** menu destination. Show the server's market prices, chart, successful readings and durable market-query history (Latest 25, View All, Resumido). Do not mount the simulation panel, adaptive decisions, balances, settings or simulator commands. Its polling is read-only and does not start/stop/reset the engine.
- `/trading-simulator` is the separate **Trading Simulator** menu destination, always visible regardless of session or permission. Greet a signed-in user with `Hello, <name>.` before showing the authorized content. Show existing virtual balances, settings, adaptive tracking, timing, start/reset, pause/resume and manual refresh. Do not duplicate the Bitcoin Tracker panel here; link to it.
- Direct entry/reload is supported on both routes. Anonymous simulator entry shows a login icon and a link to Login. Signed-in users without permission see `Hello, <name>.` and exactly `Lamentamos, usted no tiene acceso a esta sección.` No protected reads or controls are mounted before authorization. Login and logout update route permissions without a page reload; navigation remains visible. Session expiry/revocation removes access; errors fail closed with retry.
- Login remains available to other users. Its text and Home must reflect these separate permissions; simulator menu and Home card are always visible; entering the route performs the access check. Successful login offers an owner simulator link. Logout/route changes never reset funds or pause the engine.

## Identity and API authority
- Only the Google account with verified email `aribecker2@gmail.com` may use the simulator. Match the complete email case-insensitively; do not strip dots, plus suffixes or match display names. Google `email_verified` must be true. Other providers, missing/unverified email, invalid/expired/revoked tokens deny access.
- Preserve existing server-owned opaque bearer sessions and PKCE exchange. Add server-computed boolean `canUseSimulator` to exchange and `/auth/me`; never trust email/capabilities submitted by the browser. Google identity comes only from the validated OAuth/OIDC principal.
- Require this permission before all `/api/simulation` reads, commands and nested history endpoints. Return no-store JSON 401 for missing/invalid sessions, 403 for authenticated users without permission, before parsing/executing commands or database access. Preserve CORS preflight.
- Add GET-only public `/api/bitcoin`, `/api/bitcoin/rate-queries` and `/api/bitcoin/rate-periods`. The first is an explicit market-only projection: revision, running, samples, baseline, range, count, lastPollAt, error and rateQueries. Never serialize simulation/settings, balances, ledger or controlRevision through it. History reuses the existing audit and paging semantics. No public command alias.
- The Database Explorer remains available. Reading `bitcoin_shared.simulation_state` through its row endpoint requires the same permission, preventing a bypass through raw stored JSON. Other database features retain their current contract.
- Simulator clients attach the existing bearer token. On 401/403 discard protected UI data and revalidate identity. Revalidate on route entry, tab focus and periodically; handle the declared session expiry immediately. Public tracker uses no bearer token.

## Persistence and rollout
No schema/migration or data changes. Preserve all existing tables, snapshots, balances, settings, run state and rate audit. Deploy backend before frontend, keep current Google credentials and OAuth callback URLs, and do not issue production simulation commands as verification.

## Public tracker connection recovery — 2026-10-27

A sleeping Free backend can take longer than 12 seconds to answer. The public market read must allow up to 90 seconds for each attempt, remain GET-only, cancel immediately on navigation and preserve existing snapshots during reconnection. Timeout and temporary network failures must show an actionable connection message, never raw browser abort text. Existing polling retries after a failed attempt without overlapping requests. Initial loading must explain the possible backend startup delay. Regression coverage includes a response later than 12 seconds, the 90-second timeout, caller cancellation, and automatic recovery without commands.
